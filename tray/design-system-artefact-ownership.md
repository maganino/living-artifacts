# Two sessions publish to one design-system artefact

Opened 16 October 2026 after a near-miss.

## What this is

Every living document in the shell form copies two files at publish time —
`runtime.js` and `style.css` — from one shared artefact:

**https://claude.ai/code/artifact/1e1428f7-4fab-494a-98f5-58eaec6b2a6d**
(the same artefact also resolves as `claude.ai/artifact/4iRkCEEaoaR231DMHCWPTz`)

It is regenerated by `node runtime/build.mjs ds dist/design-system` and
republished by hand. `dist/` is gitignored, so **the published artefact is the
only copy of what every document is actually running.**

## The near-miss

On 15 October a publish was refused: the artefact had been republished on
12 October by a different session, from the commit below the one in hand
(`77a0643 Section references carry a hover summary`). The guard caught it.

Resolving it cost a full read of both files and a diff. It came out clean —
the only thing the live version held that the local build did not was the old
base64 wordmark, which was the thing being replaced. **That was luck.** Two
sessions building the runtime from different commits and publishing to one
artefact will eventually collide in a way where both sides hold work the other
lacks, and the merge is a 240 KB generated file nobody can read.

## Why it is not urgent but is real

Nothing is broken today. The cost shows up only on collision, and the guard
means a collision is loud rather than silent. But the blast radius is every
living document's next publish.

## Options

1. **One owner.** A rule, not code: only publish the design system from a
   session that has just run `npm test` on a clean tree at `origin/main`.
   Cheap, and relies on discipline that already failed once.
2. **Stamp the build.** Put the commit SHA into a comment at the top of the
   generated `runtime.js`, so a read of the live file says which commit it came
   from and a diff becomes a `git diff` rather than a text compare. Small, and
   turns the expensive case into a cheap one.
3. **Stop sharing the files.** Every document carries its own inlined runtime,
   as the self-contained build already does. No shared artefact, no collision,
   at the cost of ~210 KB per document and losing the property that a runtime
   fix reaches every document on its next publish.

Option 2 does not prevent the collision, it makes it cheap. That is probably
the right trade, and it composes with option 1.

## Decided and done, 16 October 2026

**Option 2 with option 1 beside it.** `buildStamp()` in `runtime/build.mjs`
puts `living-artifacts <sha> · built <date>` at the top of both generated
files, and marks `+uncommitted-changes` when the tree is dirty, because a SHA
that does not describe the build is worse than no SHA. The skill carries the
habit under *Republishing the shared design system*: clean tree, green suite,
read the stamp — and on a refusal, take the SHA off the live file's first line
and `git diff` against it.

Option 3, every document inlining its own runtime, was rejected: it ends the
collision but gives up the property that made the shared artefact worth having,
which is that one runtime fix reaches every document on its next publish.
